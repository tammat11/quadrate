# Квадрат мечты

Локальный BI-дашборд с фронтом на статике и серверным прокси для Bitrix, Clockster и БД.

## Локальный запуск

1. Создай `.env.local` по образцу `.env.example`
2. Установи зависимости:

```bash
npm install
```

3. Запусти сервер:

```bash
npm start
```

Сайт поднимется на `http://127.0.0.1:4173/`.

Личный кабинет доступен на `http://127.0.0.1:4173/cabinet.html`.
Вход идет по WhatsApp-коду: сервер сверяет номер сотрудника из инфоблока `109`,
поле `PROPERTY_733`. Для отправки кода укажи `WHATSAPP_BOT_URL` и
`WHATSAPP_BOT_TOKEN`; без них в локальной разработке API вернет `devCode` для
ручного теста одного номера.

## База кабинета

Кабинет умеет работать без БД, но для прод-режима лучше подключить Postgres:

- `CABINET_DATABASE_URL` или набор `CABINET_DB_*`
- если `CABINET_DATABASE_URL` не задан, код попробует использовать `DB_*`
- при наличии БД сервер сам создаст нужные таблицы при первом обращении

Отдельно можно вручную инициализировать схему:

```bash
npm run db:init:cabinet
```

SQL-схема лежит в [db/cabinet-schema.sql](</Users/tammat/Documents/Квадрат мечты 1/db/cabinet-schema.sql>).
В БД сейчас сохраняются:

- аккаунты кабинета, синхронизированные из инфоблока `109`
- одноразовые коды входа
- сессии кабинета
- логи синков `cabinet_sync_runs`
- последний server-side snapshot для `/api/bootstrap`
- логи refresh-циклов `bootstrap_sync_runs`

Обновление таблицы на сайте теперь можно строить так:

- `GET /api/bootstrap` читает последний snapshot, если он уже есть в Postgres
- `GET /api/bootstrap?refresh=1` пересобирает snapshot из Bitrix/Clockster/БД и сохраняет его
- `POST /api/bootstrap/sync` можно дергать кроном или вручную для фонового обновления

## Vercel

Проект подготовлен для деплоя через Vercel:

1. Импортируй GitHub-репозиторий в Vercel
2. Добавь переменные окружения из `.env.example`
3. Нажми Deploy

Используются rewrites на `api/index.js`, поэтому фронт и API работают из одного проекта.
